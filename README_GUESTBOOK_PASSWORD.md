# 방명록 작성자 비밀번호 기능 적용 안내

적용 전에 Supabase 데이터베이스를 백업하세요.

## 적용 순서

1. 기존 방명록을 아직 설치하지 않은 신규 프로젝트라면 `supabase-gallery-guestbook.sql`을 먼저 실행합니다.
2. Supabase SQL Editor에서 `supabase-gallery-guestbook-password-v2.sql` 전체를 실행합니다.
3. 현재 작성된 방명록을 모두 삭제하려면 2번이 성공한 뒤 `supabase-gallery-guestbook-clear-current.sql`을 별도로 실행합니다.

3번은 복구할 수 없는 일회성 정리 작업입니다. 게임, 랭킹, 참가 코드, 관리자 데이터는 건드리지 않습니다.

## 변경 내용

- 새 글은 4~8자리 숫자 비밀번호가 필요합니다.
- 비밀번호는 pgcrypto bcrypt 해시만 저장하며 평문은 저장하지 않습니다.
- 공개 목록 RPC는 비밀번호와 해시를 반환하지 않습니다.
- 일반 사용자는 테이블을 직접 UPDATE/DELETE할 수 없고 전용 RPC에서만 비밀번호를 검증합니다.
- 글별·클라이언트별로 15분 동안 5회 실패하면 비밀번호 확인이 잠깁니다.
- 기존 글은 `password_hash = null`로 유지되어 작성자가 수정·삭제할 수 없고 관리자만 삭제할 수 있습니다.
- 기존 관리자 삭제 RPC는 로그인한 관리자 권한을 서버에서 검증하므로 작성자 비밀번호가 필요하지 않습니다.

클라이언트 토큰 기반 제한은 기본적인 자동 대입 공격을 줄이기 위한 장치입니다. 공개 행사의 공격 위험이 높다면 Supabase Edge Function과 CAPTCHA를 추가하는 것을 권장합니다.
